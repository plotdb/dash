# subset 與 scope 機制重構

把目前掛在 `@makechart/base` 上的 subset 機制搬進 `@plotdb/chart` 核心，
並為 chart 實例建立一套有邊界的 namespace 機制，取代現在直接改寫實例的做法。

已完成。以下是與 user 討論定案的計畫，實作結果與計畫一致，差異記在最後一節。


## 背景

demo 目前可跑的 subset / crossfilter 功能是這樣接起來的：`@makechart/base` 在
`pubsub.on \init` 裡包掉 `opt.mod.parse` 與 `opt.mod.config`，然後在 `new chart(...)`
之後直接往實例上加東西：

    c._subset = ...
    c.set-subset = (raw) -> ...
    c.set-raw = (raw, binding, reinit) -> ...     # 包掉原本的
    c.filter-dims = -> ...
    c.can-filter = -> ...
    c.subset-mode = -> ...
    c.subset-ratio = (d, k, i) -> ...
    c.subset-color = (color, fade) -> ...

包 `mod.xxx` 那半是 `@plotdb/chart` 支援的擴充點，沒有問題。改實例那半是繞路，
原因是核心缺兩個東西：

 - `setRaw` 的物件形式只解構 `raw` / `binding` / `reinit`，其餘 key 直接丟掉，
   所以要從 `{raw, binding, subset}` 裡撈 `subset` 只能包掉實例的 `setRaw`
 - 沒有辦法替實例加工具方法，而 pie / bar 的 mod 裡需要寫成 `@subsetMode()`
   ( mod 方法裡的 `@` 是 chart 實例 )

連帶的第三個問題是 mod 自己的工具方法也不在實例上，只能寫
`self.mod.toggleSelect.call self, e, n`，實作過程中已經因此吃過一次
`is not a function`。


## 決定

subset 進 `@plotdb/chart` 核心，不留在 base。

理由是 subset 與 `filter` 是同一層級的概念 —— 同一份 binding、同一份 schema，
另一份被篩過的資料 —— 而 `filter` 本來就在核心。放在 base 等於把資料層的通用概念
綁在特定繪圖技術上：base 綁死 d3，未來 webgl 的圖表不會用它，但一樣需要 subset。

實例的 namespace 由核心宣告，擴充套件不能自己開新 scope。這是刻意的摩擦：
要開新 scope 就得改核心。

    # 核心宣告的 scope 註冊表. 只有核心能加, 這裡就是完整清單
    chart.scopes =
      subset: {set, mode, ratio, color}

    # 建構時逐 scope 建一份綁到實例的物件
    bind-scope = (tbl, over) ~>
      ret = {}
      for k, f of ({} <<< tbl <<< (over or {})) => ret[k] = f.bind @
      ret

    for name, tbl of chart.scopes => @[name] = bind-scope tbl, @mod[name]
    @local = bind-scope (@mod.local or {})

呼叫端變成 `@subset.mode()`、`@local.toggleSelect(e, n)`。

`local` 是核心保留的名字，核心只保證這個字不會被別人佔走，內容完全不管
( 核心也不可能知道裡面有什麼 )。

mod 若要覆寫 scope 裡的個別函式，在建構時合併掉，執行期不必每次判斷。
需要呼叫核心預設實作時，靜態表本來就取得到：`chart.scopes.subset.mode.call @`。


## 範圍

### @plotdb/chart

 - `chart.scopes` 註冊表與 `bind-scope`，在建構時建立 `@<scope>` 與 `@local`
 - 建構時比對實例與原型上已有的成員，撞名直接拋
 - subset 通道：`setRaw({raw, binding, subset})` 核心直接收
 - subset 對齊邏輯搬進核心的 `parse`，在呼叫 `mod.parse` 之前掛上 `d.subset`
   ( 目前在 base 的 `parse-subset`，含 `nparse`、`is-numeric`、`align-dim` )
 - `shrink` 模式直接用子集覆寫數值維度的處理，一併搬入
 - `cfg.common.subset.{mode, opacity, fade}` 進核心的 config 預設
 - `filterDims()` / `canFilter()` 進核心。核心讀 `mod.filterDims`，
   沒宣告就退回「有 `mod.filter` 就是 `['name']`」

`mod.setRaw` hook 原本是為了讓 base 攔截 payload 才需要，subset 進核心之後
不一定還有必要，實作時再判斷。

### @makechart/base

 - 移除全部實例改寫，`subset-*` 六個方法與 `_subset` 狀態隨 subset 一起搬走
 - `common-config` 一併移除
 - 包 `opt.mod.parse` 的動作可以拿掉
 - 預期回到接近原狀 ( 字型、layout、d3 依賴 )，目前的 `+112` 行大部分會消失

### 五張圖

 - `@subsetMode()` / `@subsetColor()` / `@subsetRatio()` 改成 `@subset.*`
 - 自己的工具方法搬進 `mod.local`，呼叫端從 `self.mod.foo.call self, ...`
   改成 `self.local.foo(...)`
 - 影響：pie ( `toggleSelect`、`filterToLegend`、`legendToFilter` )、
   line ( `syncBrush`、`legendToFilter` )、percent-list ( `pickedOf` )、
   taiwan-map ( `toggleSelect`、`pickedOf` )、bar ( 只有 `@subset.*` 的改名 )
 - `mod.filterDims` 維持宣告在各圖上，由核心讀

### dash

不用動。`chart.filterDims()` / `chart.canFilter()` 名字與語意都不變，只是換人提供。


## 被否決的方案

`mod.mixin.<scope>.*` —— 多一層巢狀，唯一買到的是「讓核心知道哪些 key 是 scope」，
但 scope 由核心宣告之後這個問題根本不存在。而且 `@mixin.subset.mode()` 比
`@subset.mode()` 難讀。

`mod.scopes = <[subset]>` 白名單 —— 同上，scope 既然是核心開的就不需要 mod 來登記。

「非保留字且值為物件的 key 就是 scope」黑名單 —— 靠形狀判斷，
而且擴充套件可以自由開 scope，與「避免自由擴充 api」的原則相反。

`chart.prototype.subset = {...}` —— 那份 template 永遠會被實例屬性遮住，
放 prototype 等於宣告一條走不到的查找路徑。更糟的是失敗模式：萬一建構時沒建好
`@subset`，呼叫會悄悄掉到 prototype 上那份未綁定的物件，`this` 變成 subset 物件本身，
行為錯但不報錯。放靜態上就是 `undefined`，當場炸。


## 驗收

demo 行為不變是唯一標準。重構前後 `web/src/pug/initiative/1st/` 的以下操作結果要一致：

 - bar 框選、pie wedge 點選、taiwan-map 縣市點選發出 filter
 - pie / line 的 legend crossfilter，含「全選」與「全不選」的區別
 - line 的 brush 發 range filter，且來回同步不會漂移
 - `partial` 在 bar / pie / percent-list / line 上的呈現
 - percent-list 與 taiwan-map 依自己的選取畫淡

`@plotdb/chart` 的改動必須是純新增：沒有傳 subset 的圖 `d.subset` 不存在，
行為與現在完全相同。


## 注意事項

發版順序有相依：`@plotdb/chart` 先，`@makechart/base` 次之，其餘五張圖最後。
開發期間用 `tool/sync-charts.sh` 覆蓋。

另有兩個相容性問題待 user 決定，與本次重構獨立：pie 的 wedge 與 taiwan-map 的縣市
現在點下去會選取並改變外觀，對既有使用者是可見的行為改變。可能要改成 config 開關。


## 實作結果

計畫照做，沒有走樣。幾點值得記下來：

`@makechart/base` 回到原狀 —— `git diff` 是空的。原本預期「大部分會消失」，實際是全部，
所以這次發版不必動它。

核心不依賴 d3，所以 `subset.color` 原本用的 `d3.rgb` 換成自己認 `#rgb` / `#rrggbb` / `rgb()`
的小解析器，認不出來的顏色原樣退回 —— 畫得跟選中的一樣總比畫不出來好。palette 走的都是
十六進位字串，實際不會落到退回那條路。

`mod.setRaw` hook 最後沒有加。subset 進核心之後 `setRaw` 不必再被誰攔截，加了就是多開一個
沒人要用的擴充點。

驗收的六項在 demo 上逐項試過，行為與重構前一致；四個 panel 同時篩選時 `rowsFor` 的數字對得上
( 270 = 864 × 3/4 × 5/12 )。console 只剩原本就有的 konfig 字型警告。

新發現的一個後續問題：核心把 `common.subset` 併進每張圖的 `mod.config`，所以設定面板一律
看得到這一組，但一張圖支不支援 subset 是它自己的事 —— 沒實作的圖照樣把開關秀給使用者，
切了沒反應。user 決定先這樣，未來要補一個「這張圖不支援 / 不提供這一組」的宣告機制。
