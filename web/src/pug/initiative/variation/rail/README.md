# rail「側欄」

把四個數字立起來。左邊一整欄是指標，右邊一張主圖佔掉其餘的全部。

看畫面：`http://localhost:64500/initiative/variation/rail/`
( 入口頁在 `/initiative/variation/` )。

跟 `desk` 比，def 的結構、crossfilter 的語意、用的圖表 block 全部相同。
以下只講不同的地方。


## 改四行 area 就換了一個版面

另外五個設計的 KPI 都是橫的一排。這一版把它們放進左邊一整欄：

    area: {col: [1, 3], row: [1, 1]}
    area: {col: [1, 3], row: [2, 1]}
    area: {col: [1, 3], row: [3, 1]}
    area: {col: [1, 3], row: [4, 1]}

就這樣。版面寫在 def 裡、不在版型檔裡，所以「重排」是改幾個數字，
不必碰任何 block、也不必碰 `dash.board`。

立起來之後每個數字有一整欄的寬度，字級可以放到 42px，
四個數字變成一條可以一眼掃完的清單，而不是四張要分別讀的卡片。


## 側欄的代價

四個數字直的疊起來要吃掉四列，右邊的圖只能跟著切這四列。
一開始行高寫成 `fr` 去填滿視窗，結果在 800px 高的筆電上，
右下角兩格各只分到 130px —— 扣掉標題跟那條粗線之後畫不出東西來。

所以這一版的行高也是絕對值，整頁往下捲（跟 report、pocket 同一招，
一樣要蓋掉 `dash.css` 的 `.dash { height: 100% }`）。

要嘛給圖足夠的高度然後讓頁面捲，要嘛把數字放回頂上那一排。
這是這個版面真正的取捨，不是樣式問題。


## 沒有卡片, 也沒有框

每一格的上緣是一條 3px 的粗線。那條線是標題的一部分，不是分隔線 ——
它跟標題一起構成「這是一節的開頭」。

「篩選中」就是那條線換成強調色。這一版沒有邊框可以亮、沒有陰影可以深，
只有這條線（report 的 1px 細線是同一個想法的輕量版）。

進場動畫也跟著改成整面一起淡入，不逐格：沒有框的格子一塊一塊亮起來，
看起來像畫面壞掉。


## 一個紅, 其餘全是灰階

報紙的色票。顏色只用在需要分辨的地方：

    cat: colors: <[#d7263d #1f4ea8 #0a0c0f #9aa1ab]>   # 紅、藍、黑、灰
    geo: colors: <[#0a0c0f]>                           # 長條圖是全黑的

長條圖全黑是這一版最明確的一句話：一張單色圖該用最黑的那個黑，
紅色留給「現在被選中的是哪一塊」。

深色模式把紙換成墨，但關係不變 —— 最強的那個色從黑換成白，
強調色提亮一級（同一個紅在黑底上看起來更暗）。


## 這一版沒做的

 - 窄螢幕沒有重排。側欄在 900px 以下會被擠成兩三個字寬
 - 沒有 def 編輯器
 - 側欄沒有釘住 ( sticky )。捲下去看底下兩張圖時, 指標會跟著捲走
