# design-4「口袋」

給一支手機。一欄到底、整頁往下捲，主要動作放在拇指構得到的地方。

看畫面：`http://localhost:64500/initiative/2nd/design-4/`
( 入口頁在 `/initiative/2nd/` )。

跟 `design-1` 比，def 的結構、crossfilter 的語意、用的圖表 block 全部相同。
以下只講不同的地方。


## 前提只有三句

 - **畫面只有一欄寬** —— `def.layout.col` 從 12 欄變成 2 欄
 - **操作的是拇指** —— 點擊目標一律 32px 以上，主要動作在畫面底部
 - **人是站著看的** —— 一次只看一格，每一格都要自己說得完整

值得記一筆的是：換成手機**沒有動到 `dash.board` 一行**。版面是 def 裡的
`col` / `row`，一欄的版面就是 `col` 只給兩欄 —— 格線系統本來就不在乎自己有多寬。


## 兩欄, 不是一欄

四個 KPI 排成 2x2，圖一律跨兩欄。直式手機一行塞不下四個數字，
塞得下也讀不到 —— 所以「一欄的版面」實際上要兩欄才排得出來。

行高跟 design-2 一樣全部是絕對值，而且給得比桌機大方
（趨勢圖 15em、地圖 19em）：一次只看一格，不必省空間給隔壁。


## 拿掉的互動

    brush: {enabled: false}

手機上不開框選。拖曳在一個會捲動的頁面裡，跟捲動搶的是同一個手勢 ——
使用者想捲，圖以為在框選。這不是樣式問題，是這個版面本身造成的，
所以改在 def 裡關掉，不是在 CSS 裡擋。

趨勢圖的 legend 也從 `direct` 換回 `bottom`：一欄的寬度裡，
寫在線末端的標籤會蓋到資料。長條圖則用上 `xaxis.label.direction: auto`，
六個縣市的名字在這個寬度一定撞在一起。


## 狀態放哪裡

 - 篩選中的欄位是一排可以橫向捲的 chip，排在頁首底下
 - 「清除篩選」常駐在畫面底部，一個 44px 高的按鈕
 - 每一格自己的「篩選中」是一顆 32px 的藥丸，點了只清那一格

手機上沒有 hover，所以狀態只能靠看得見的東西說，不能等人把游標移上去。


## def 是唯讀的

在 320px 寬的螢幕上改 JS 物件字面量不是編輯，是受罰。
這一版把 def 放在文件最後一個可以展開的區塊裡，只印出來 ——
要改去 design-1 的抽屜或 design-2 的附錄。


## light / dark

深色模式的卡片**比底色亮**，跟桌機的習慣相反。
手機在暗處是房間裡唯一的光源，大面積的亮色只能給卡片、不能給背景。

色票兩個模式都比桌機保守：螢幕小，同樣一塊顏色佔的視角大得多，太飽和會晃眼。


## 這一版沒做的

 - 沒有下拉更新、沒有慣性捲動的處理。它是一個網頁, 不是一個 app
 - 橫置沒有另外排。轉成橫的就是一欄變寬, 沒有變成兩欄
 - 沒有離線快取
